# 文字起こし自動化ワークフロー - 詳細計画書

**作成日**: 2025-12-17
**ステータス**: 計画確定・実装待ち

---

## 1. 目的・KGI

### 1.1 目的

ゆめマガ制作のインタビュー録音データを自動で文字起こし・整理し、制作工程を効率化する。

### 1.2 KGI

- 録音データをGoogle Driveにアップロード後、ワンクリックで文字起こし・整理が完了
- 手動での文字起こし作業をゼロにする
- 整理済みテキストがそのまま記事作成に使える状態で出力される

---

## 2. ワークフロー仕様

### 2.1 トリガー

**Form Trigger**を使用し、実行時に月号を入力する。

| 入力項目 | 例 | 説明 |
|---------|-----|------|
| 月号 | 2026_01 | 処理対象の月号（フォルダ名と一致） |

### 2.2 処理フロー

```
1. Form Triggerで月号入力（例: 2026_01）
2. 対象カテゴリ（A, H, I, K, C）の該当フォルダを走査
3. 録音データフォルダ内のファイルを取得
4. 各ファイルに対して:
   a. 文字起こしフォルダに同名.txtが存在するか確認
   b. 存在する → スキップ
   c. 存在しない → 以下を実行:
      i.   Whisper.cppで文字起こし（生テキスト）
      ii.  Geminiで整理（カテゴリ別プロンプト使用）
      iii. 結果を文字起こしフォルダに保存
5. ステータス更新（進捗管理シート）
```

### 2.3 スキップ判定

| 録音ファイル | 文字起こしファイル | 判定 |
|-------------|------------------|------|
| interview.m4a | interview.txt が存在 | スキップ |
| interview.m4a | interview.txt が存在しない | 実行 |

**重要**: 同名ファイル（拡張子違い）で判定。既に文字起こし済みのファイルは絶対にスキップする。

## 4. カテゴリ別プロンプト

### 4.1 A. メインインタビュー用

```
【基本指示】
あなたは雑誌記事の編集者です。以下の文字起こしテキストを、記事として読みやすく整理してください。

【カテゴリ】
A. メインインタビュー（P4-5見開き）

【必須ルール】
1. 捏造・追加の禁止: 文字起こしにない内容は絶対に追加しない
2. 削除・整理のみ可: 不要な部分の削除、順番の整理、表現の改善のみ実施
3. マークダウン記法の禁止: プレーンテキストで出力

【整理の要点】
・質問は「— 」で始める（全角ダッシュ + 半角スペース）
・回答は質問の後に改行して段落で記載（マーク不要）
・1つの回答: 150-250文字程度を目安
・話し言葉→書き言葉への変換
・重複表現の削除（ただし人物の個性が出ている表現は残す）
・固有名詞や専門用語で誤りがある場合は【要確認】マークを付ける

【出力形式】
— [質問内容]

[整理後の回答]

— [質問内容]

[整理後の回答]
```

## 5. n8nノード構成

### 5.1 全体構成

```
[Form Trigger]
    ↓ 月号入力
[Set Categories]
    ↓ 対象カテゴリ配列を設定
[Loop Over Categories]
    ↓ 各カテゴリを処理
[Get Category Folder]
    ↓ Google Driveでフォルダ取得
[Get Month/Company Folders]
    ↓ 月号フォルダまたは企業フォルダを取得
[Get 録音データ Folder]
    ↓ 録音データフォルダを取得
[Get Audio Files]
    ↓ 音声ファイル一覧を取得
[Loop Over Files]
    ↓ 各ファイルを処理
[Check Existing Transcription]
    ↓ 文字起こしフォルダに同名txtがあるか確認
[IF: Exists?]
    ├─ Yes → [Skip]
    └─ No → [Download Audio]
              ↓
           [Execute Whisper]
              ↓
           [Get Category Prompt]
              ↓
           [Gemini: Organize Text]
              ↓
           [Upload to 文字起こし Folder]
              ↓
           [Update Status]
```

### 5.2 主要ノードの設定

#### Form Trigger
- フィールド: 月号（テキスト入力）
- 例: `2026_01`

#### Execute Whisper (Execute Command)
```bash
/opt/whisper.cpp/build/bin/whisper-cli \
  -m /opt/whisper.cpp/models/ggml-base.bin \
  -l ja \
  -otxt \
  -of /tmp/output \
  /tmp/{{ $json.fileName }}
```

#### Gemini (HTTP Request)
- Method: POST
- URL: `https://generativelanguage.googleapis.com/v1beta/models/gemini-pro:generateContent`
- Body: カテゴリ別プロンプト + 文字起こしテキスト

## 6. 実装手順

### Step 1: n8nでワークフロー作成

1. n8n（http://localhost:5678）を開く
2. 新規ワークフロー「ゆめマガ文字起こし」を作成
3. 上記ノード構成に従ってノードを配置・接続

### Step 2: Google Drive認証設定

1. 既存のGoogle Drive Credentialを使用
2. 各Google Driveノードに認証を設定

### Step 3: Gemini API設定

1. Google AI StudioでAPIキーを取得
2. n8nでHTTP Request用のCredentialを作成
3. APIキーをヘッダーに設定

### Step 4: カテゴリ別プロンプトの設定

1. Set nodeまたはCode nodeでカテゴリ別プロンプトを定義
2. ループ内でカテゴリに応じたプロンプトを選択

### Step 5: テスト実行

1. 短い音声ファイル（1分程度）でテスト
2. 各カテゴリで動作確認
3. スキップ判定が正しく動作するか確認

### Step 6: 本番実行

1. Form Triggerで月号を入力
2. ワークフロー実行
3. 結果を確認

## 7. テスト方法

### 7.1 単体テスト

| テスト項目 | 確認内容 |
|-----------|---------|
| Whisper.cpp | 音声ファイルが正しく文字起こしされるか |
| Gemini | プロンプトに従って整理されるか |
| スキップ判定 | 既存ファイルがスキップされるか |
| フォルダ走査 | 全カテゴリが正しく走査されるか |

### 7.2 統合テスト

1. テスト用の録音データを各カテゴリにアップロード
2. ワークフローを実行
3. 文字起こしフォルダに結果が保存されるか確認
4. 再度実行してスキップされるか確認

## 9. 注意事項

### 9.1 絶対遵守

- **スキップ判定は必ず実装する**: 同名ファイルがあれば絶対にスキップ
- **捏造禁止**: AIプロンプトで「追加しない」を強調
- **カテゴリ別プロンプト**: 各カテゴリの出力形式を厳守

### 9.2 フォルダ構造の違い

- A, H, I, K: `{カテゴリ}/{月号}/録音データ/`
- C: `{カテゴリ}/{企業名}/録音データ/`（月号ではなく企業名）

### 9.3 エラーハンドリング

- 音声ファイルが長すぎる場合はタイムアウト対策が必要
- Gemini APIのレート制限に注意

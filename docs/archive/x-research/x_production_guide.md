## Step 4: 追加調査

### ★最重要★

**Antigravityの情報を元に追加調査を行い作成する**

Antigravityの出力はあくまで「叩き台」。Claude Codeは以下を行う：

1. **トレンドランキングの確認** - step2からトップツールを把握
2. **公式ソースの検証** - step3のURLが正確か確認
3. **追加情報の取得** - 公式ドキュメント、Zenn記事などから深掘り
4. **切り口の展開** - 1ツール × 5切り口で投稿アイデアを拡張

### 切り口

| 切り口 | キーワード |
|--------|-----------|
| 資料作成 | スライド、PDF、レポート |
| 動画生成 | 動画、ムービー、映像 |
| 画像生成 | 画像、イラスト、バナー |
| アプリ開発 | アプリ、実装、コード |
| バイブコーディング | Cursor、Claude Code、Windsurf |

```
【7】まとめ + CTA
    箇条書きで要約

```

**スレッド投稿の内容ルール:**

| ✅ 書くべき内容 | ❌ 書いてはいけない内容 |
|----------------|----------------------|
| ユースケース | UI操作手順 |
| 優れている点 | 「〇〇をクリック」等の具体的操作 |
| メリット | スクリーンショットの説明 |
| 活用シーン | バージョン固有の設定手順 |
| 抽象度が高い説明 | すぐ変わる可能性のある詳細 |

**理由**: UI手順は変更されると誤情報になる。抽象度が高い内容は多少の誤差があっても問題ない。

## URLルール（重要）

### 基本方針

**URLは必須ではない。価値があるものだけ掲載する。**

### 掲載する価値があるURL

全ての条件を満たす場合のみ掲載：

| 条件 | 説明 |
|------|------|
| ① 読者にとって価値がある | 「これ見たい！」と思うリソース |
| ② 正確に取得できる | URLが確実に存在・動作する |
| ③ 信頼性がある | よく読まれている、確かな情報源 |

**価値があるURLの例:**
- Zennの人気記事
- 有益なテンプレート・ツール
- 公式の詳細ガイド（トップページではなく）

### 掲載しないURL

| ケース | 理由 |
|--------|------|
| ただの公式トップページ | 価値が低い |
| 根拠のためだけのURL | 読者視点でない |
| 取得できないURL | リンク切れリスク |
| 信頼性が不明なURL | 裏付けがない |

### 結論

- スレッド投稿にURLは**必須ではない**
- 価値あるZenn記事などがあり、確実に取得でき、信頼性があるなら掲載
- なければ**リンクなしでOK**

## ★URL検証ステップ（Announcement必須）★

### なぜ必要か

150投稿生成時に、AnnouncementのURLが「汎用トップページ」になってしまう問題が発生した。
今後同じ問題を防ぐため、Announcementパターンでは必ずURL検証を行う。

### 検証フロー

```
1. 投稿内容からツール名・機能名を特定
   ↓
2. WebSearchで公式発表記事を検索
   検索例: "[ツール名] announcement blog 2025"
   ↓
3. 以下をチェック
   ├── URLがトップページではないか？
   ├── パスに /blog/, /news/, /updates/ 等が含まれるか？
   └── 投稿内容と発表記事の内容が一致するか？
   ↓
4. 検証済みURLをreply_contentに設定
```

### URL検証ルール

| チェック項目 | OK例 | NG例 |
|--------------|------|------|
| パス有無 | `/blog/xxx`, `/news/xxx` | `/` のみ |
| 具体性 | 記事タイトルや日付を含む | 汎用ページ |
| 発表内容との一致 | 投稿で紹介する機能の発表記事 | 関係ない記事 |

### 具体例

| ツール | ❌ NG（トップページ） | ✅ OK（発表記事） |
|--------|----------------------|------------------|
| Suno | `https://suno.com/` | `https://suno.com/blog/suno-studio` |
| Claude | `https://www.anthropic.com/` | `https://www.anthropic.com/news/claude-opus-4-5` |
| Canva | `https://www.canva.com/` | `https://www.canva.com/newsroom/news/affinity-free/` |
| Manus | `https://manus.im/` | `https://manus.im/blog/manus-max-release` |

### 公式発表URLが見つからない場合

| 選択肢 | 説明 |
|--------|------|
| ① URLを掲載しない | `reply_content`を空にする |
| ② 信頼できる解説記事を使用 | Zenn等の人気記事 |
| ❌ 禁止 | トップページURLをそのまま使用 |

## 信頼度ルール（最重要）

| ルール | 内容 |
|--------|------|
| 不確実な情報は絶対NG | 有益でも不確実なら投稿しない |
| ハルシネーション禁止 | AIが勝手に判断・解釈しない |
| 古い情報混入禁止 | カットオフ以前の情報は確認必須 |
| 根拠必須 | 投稿内容に対して確実な根拠を持つ |

### 鮮度チェックの考え方

**重要: インフルエンサーの情報を「架空」と判断しない**

```
【問題パターン】
インフルエンサー: 「GPT-5.2がすごい！」
        ↓
裏付け調査: GPT-5.1の情報しか出てこない
        ↓
❌ 通常のAI判断: 「5.2は架空のバージョン」として切り捨て
        ↓
✅ 正しい判断: 調査ソースが追いついていない可能性
```

**チェック対象ツール（鮮度の目安）:**

| 企業 | ツール | 最低バージョン |
|------|--------|---------------|
| Google | Gemini | 3.0以上 |
| OpenAI | GPT | 5.2以上 |
| OpenAI | Sora | 2以上 |

## 日本語表現チェック

### 禁止表現

| カテゴリ | ❌ NG例 | ✅ OK例 |
|----------|---------|---------|
| 直訳調 | 「これは革命的なツールです」 | 「業務効率化に役立つツールです」 |
| 助詞抜け | 「〇〇の衝撃」「〇〇革命」 | 「〇〇による大きな変化」 |
| 上から目線 | 「〜ですよ」「〜ますよ」 | 「〜です」「〜ます」 |
| 絵文字乱用 | 「すごい！🔥🚀✨💯」 | 「すごい！」（1つまで） |
| 煽り表現 | 「衝撃」「革命」「神」「最強」 | 具体的な価値を説明 |

### 文体ルール

| ルール | 内容 |
|--------|------|
| 敬体統一 | 「です」「ます」調で統一 |
| 絵文字 | 1投稿につき1-2個まで、なくてもOK |
| 句読点 | 適切に使用（読みやすさ重視） |
| 主語明示 | 主語が曖昧にならないようにする |

## 禁止事項（まとめ）

### 情報の正確性

1. データのシミュレーション・捏造
2. ハルシネーション（勝手な判断・解釈）
3. 古い情報の混入（カットオフ以前の確認なし使用）
4. インフルエンサーの情報を「架空」と判断すること

### 投稿フォーマット

5. 1ツイート目/本文へのリンク配置
6. 画像プロンプトへの日本語混入
7. スレッド投稿にUI操作手順を含めること

### 日本語表現

8. 英語の直訳的表現
9. 「ですよ」「ますよ」等の上から目線
10. 絵文字の乱用（1投稿2個以上）
11. 煽り表現（「衝撃」「革命」「神」「最強」）

**問題が発生した場合は報告して停止すること。**

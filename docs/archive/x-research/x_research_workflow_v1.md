# X Research Workflow v1

## Overview

YouTubeインフルエンサーからトレンドを収集し、X向けスレッド投稿を生成するワークフロー。

**役割分担：**
- **Antigravity**: 事実ベースで情報収集（YouTubeタイトルからツール名・切り口を抽出）
- **Claude Code**: 裏付け調査、スレッド作成、品質チェック

| Step | 内容 | 出力 |
|------|------|------|
| 0 | 初期化 | ディレクトリ作成 |
| 1 | トピック収集（100本） | step1_topics.json |
| 2 | 正規化 + トレンドランキング | step2_trend_ranking.json |
| 3 | 根拠取得（公式ドキュメント） | step3_sources.json |
| 4 | スレッド生成 | x_thread_ideas.json |
| 5 | 品質チェック | quality_check_report.json |

---

## 重要な方針

### 信頼度が最重要

| 原則 | 内容 |
|------|------|
| 不確実な情報は絶対NG | 下手に有益なことを言おうとして不確実な情報を投稿しない |
| ハルシネーション禁止 | AIが勝手に判断・解釈しない |
| 古い情報混入禁止 | カットオフ以前の情報を確認せずに使わない |
| 根拠必須 | 全ての情報に対して確実に根拠を取る |

### 鮮度チェックの考え方

**重要: インフルエンサーの情報を「架空」と判断しない**

```
【問題パターン】
インフルエンサー: 「GPT-5.2がすごい！」
        ↓
裏付け調査: GPT-5.1の情報しか出てこない
        ↓
❌ 通常のAI判断: 「5.2は架空のバージョン」として切り捨て
        ↓
✅ 正しい判断: 調査ソースが追いついていない
```

**チェック対象ツール（鮮度の目安）**

| 企業 | ツール | 最低バージョン |
|------|--------|---------------|
| Google | Gemini | 3.0以上 |
| Google | Antigravity, Nanobanana Pro, Flow | - |
| OpenAI | GPT | 5.2以上 |
| OpenAI | Sora | 2以上 |
| Anthropic | Claude Code | - |
| - | NotebookLM, Genspark, Cursor | - |

**判断基準:**
- インフルエンサーがこれらを取り上げている → 実在する最新情報
- 裏付け調査で古いバージョンしか出ない → 調査ソースが古い
- 「架空」と切り捨てない → インフルエンサーの情報を信頼

## Step 1: トピック収集（100本）

### 目的

**YouTuberの投稿タイトル100本からツール名と切り口を抽出する。**

### 対象（5人）

| # | 名前 | YouTube URL |
|---|------|-------------|
| 1 | チャエン | https://www.youtube.com/@chaen-ai-lab |
| 2 | mikimiki | https://www.youtube.com/@mikimikiweb |
| 3 | AIサボロー | https://www.youtube.com/@ai-saborou |
| 4 | 木内翔大 | https://www.youtube.com/@SHIFT-AI_kiuchiAI |
| 5 | KEITO | https://www.youtube.com/@keitoaiweb |

### 収集条件

| 項目 | 値 |
|------|-----|
| 期間 | 過去90日 |
| 収集数 | 過去90日の動画を全て収集（上限20本/人） |
| 目標収集数 | 100本（5人 × 20本） |

### 抽出するもの

| フィールド | 内容 |
|-----------|------|
| tool_name | ツール名（生データ） |
| angle | 切り口（資料作成/動画生成/画像生成/アプリ開発/バイブコーディング） |
| title | 動画タイトル |
| url | 動画URL |

### 切り口の分類

| 切り口 | キーワード例 |
|--------|-------------|
| 資料作成 | スライド、PDF、レポート、ドキュメント |
| 動画生成 | 動画、ムービー、映像、Sora |
| 画像生成 | 画像、イラスト、バナー、サムネ |
| アプリ開発 | アプリ、開発、実装、コード |
| バイブコーディング | Cursor、Claude Code、Windsurf |

    }

## Step 3: 根拠取得（公式ドキュメント）

### 目的

各トピックに対して公式ドキュメント・権威資料から根拠を取得する。

### 参照先の優先順位

| 優先度 | ソース | 例 |
|--------|--------|-----|
| 1 | 公式サイト・公式ブログ | openai.com, blog.google |
| 2 | 公式発表（プレスリリース） | PR TIMES, 企業ニュースルーム |
| 3 | 権威ある企業の公開資料 | DeNA, メルカリ, 松尾研 |
| 4 | 技術ブログ（公式/半公式） | Zenn（公式アカウント）, note |

### 重要: 鮮度チェック

**インフルエンサーが取り上げたバージョンが調査で出てこない場合:**
- ❌ 「架空のバージョン」と判断しない
- ✅ 調査ソースが追いついていないと認識
- ✅ インフルエンサーの情報を信頼

### 出力

**step3_sources.json**
```json
{
  "sources": [
    {
      "tool_name": "Gemini 3.0",
      "official_url": "https://blog.google/...",
      "key_features": ["機能1", "機能2"],
      "release_date": "2025-12-XX",
      "verified": true
    }
  ]
}
```

## Step 4: スレッド生成

### 投稿パターン（3種類）

| パターン | 頻度 | 内容 |
|----------|------|------|
| **① スレッド投稿** | 1日1回 | Gem×NotebookLM型（慎重に作成） |
| **② 画像付き投稿** | 複数回/日 | Nanobanana Proで図解生成 |
| **③ 公式発表・アップデート** | 適宜 | 権威性のある情報をシェア |

### パターン①: スレッド投稿（Gem×NotebookLM型）

**参考**: `thread-sample-gem-notebooklm.md`

**構造:**
```
【1ツイート目】フック（Stop-Scroll）
├── リンクなし
├── 280文字以内（Show more回避）
└── 何が起こった→どう変わる→スレッド内容予告
        ↓
【2ツイート目】ソース + 理由1
├── 公式URLを配置（1つのみ）
└── 【見出し】形式で解説
        ↓
【3〜N-1ツイート目】本文（Main Value）
├── 番号付き（1/5形式）
├── 【見出し】形式
└── 具体的なプロンプト・手順を含む
        ↓
【最終ツイート】まとめ + CTA
├── 箇条書きで要約
├── フォロー誘導
└── @アカウント名
```

### パターン②: 画像付き投稿

**画像生成ルール:**

| ルール | 内容 |
|--------|------|
| 日本語禁止 | 図解は必ず英語で生成 |
| 単語制限 | 日本人が見て理解できる単語のみ |
| OK例 | database, WEB, API, AI, workflow |
| NG例 | 複雑な英文、専門用語の羅列 |

### パターン③: 公式発表・アップデート

**構造（資料紹介型）:**
```
[企業名]の「[資料名]」が有益。

[ターゲット]にとって、「[概念1]」から「[概念2]」、さらには「[概念3]」といった[学べること]が学べる。

こちら👉
```

**リンク配置:**
- 1ツイート目: リンクなし（アルゴリズム対策）
- 2ツイート目: ソースURL

## Step 5: 品質チェック

### CRITICAL チェック（必須通過）

| ID | 内容 |
|----|------|
| C-01 | 事実の捏造がない |
| C-02 | 全情報に根拠（ソースURL）がある |
| C-03 | 古いバージョンを使用していない |
| C-04 | インフルエンサーの情報を「架空」と判断していない |
| C-05 | 1ツイート目にリンクがない |

### HIGH チェック

| ID | 内容 |
|----|------|
| H-01 | 1ツイート目が280文字以内 |
| H-02 | 2ツイート目以降にソースURLがある |
| H-03 | 最終ツイートにCTA（フォロー誘導）がある |
| H-04 | 画像の図解が英語のみ |

## Xアルゴリズム対応（2025年版）

### 重要ポイント

| 項目 | 内容 |
|------|------|
| 外部リンク | HEAVY PENALTY → 1ツイート目は絶対リンクなし |
| リンク配置 | 2ツイート目以降 or プロフ誘導 |
| Dwell Time | 長く読ませるほど有利 |
| 初動15-60分 | この間のエンゲージメントが鍵 |
| Premium | 30-40%可視性ブースト |

### リンク戦略

| 戦略 | 方法 |
|------|------|
| 重要ソース1つ | 2ツイート目に配置 |
| 複数リンク必要 | 「詳細はプロフィールから」で誘導 |

---

## 禁止事項（全ステップ共通）

1. データのシミュレーション・捏造
2. ハルシネーション（勝手な判断・解釈）
3. 古い情報の混入（カットオフ以前の確認なし使用）
4. インフルエンサーの情報を「架空」と判断すること
5. 1ツイート目へのリンク配置
6. 画像への日本語混入

問題が発生した場合は**報告して停止**すること。

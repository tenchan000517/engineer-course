## 設計要素1：冒頭3秒の「認知的不協和」設計

### なぜ「論外」から始めるのか

**表面的理解**: 注意を引くため
**本質**: 視聴者の「既存の信念」を破壊し、認知的不協和を起こすため

### 認知的不協和とは

人は「自分の信念」と「新しい情報」が矛盾すると不快感を感じ、
**その不快感を解消するまで離脱できない**。

### 設計ステップ

```
Step 1: ターゲットの「今の信念」を特定する
        ↓
Step 2: その信念を「否定」するフックを作る
        ↓
Step 3: 否定の「理由」を端的に述べる
```

### 実例分析

| ターゲットの信念 | 否定フック | 不協和の強さ |
|------------------|------------|--------------|
| 「ChatGPTが最強」 | 「ChatGPT？論外」 | ★★★★★ |
| 「NISAは良い投資」 | 「NISA？論外」 | ★★★★☆ |
| 「LINEスタンプは稼げる」 | 「月100万！...と言いたいところだけど論外」 | ★★★★★ |

### 最強のフック設計式

```
[ターゲットが信じているもの]？ + [強い否定] + [端的な理由]
```

**悪い例**: 「ChatGPTはあまりおすすめしません」
→ 弱い。不協和が起きない。

**良い例**: 「ChatGPT？論外。時代遅れです」
→ 断定。不協和が最大化。

### 否定できる「信念」の見つけ方

1. **ターゲットが「当たり前」と思っているもの**
2. **多くの人が「正解」と思っているもの**
3. **メディアで「推奨」されているもの**

これを否定すると認知的不協和が最大化する。

## 設計要素2：男女掛け合いの「役割設計」

### なぜ男女の声なのか

**表面的理解**: バリエーションのため
**本質**: 視聴者に「自己投影」と「権威からの教え」を同時体験させるため

### 役割の本質

| 声 | 役割 | 視聴者の体験 |
|----|------|--------------|
| 女性（質問者） | 視聴者の代弁者 | 「自分が質問している」感覚 |
| 男性（回答者） | 権威者・先生 | 「教えてもらっている」感覚 |

### なぜこの組み合わせが効くのか

1. **質問者がいることで「疑問→解決」の構造が生まれる**
   - 一方的な説明より「対話」の方が脳に入りやすい

2. **視聴者は質問者に自己投影する**
   - 「自分もこれ知りたかった」という共感

3. **回答者の「断定」が権威性を生む**
   - 「論外」「一択」「最強」という断定
   - 迷いがない = 信頼できる

### 再現のポイント

- 質問者の声は**短く、シンプル**に（キーワードのみ）
- 回答者の声は**断定的**に（「〜かも」を使わない）
- 回答者は**理由を必ず添える**（断定の根拠）

## 設計要素3：ランキング構造の「期待値設計」

### なぜランキング形式なのか

**表面的理解**: 整理しやすいから
**本質**: 「期待値の段階的上昇」と「離脱防止」のため

### ツァイガルニク効果

**人は「未完了のタスク」を完了させたい本能がある**

ランキング形式は「1位を見るまで未完了」という状態を作り出す。
→ 1位を見るまで離脱できない。

---

### 【重要】順番は「昇順」ではない

**表面的理解**: 4位→3位→2位→1位の昇順
**本質**: 順番はシャッフルされている。1位だけが最後に固定。

#### 実際のサンプル分析

**サンプル1（AIツール）の実際の順番**:
```
論外: ChatGPT
  ↓ 「画像生成が弱い」という否定理由
3位: Nano Banana ← 論外の説明から自然に流れた（画像生成の話）
4位: Claude
2位: Google AI Studio
1位: Genspark
```

**サンプル4（SNS運用AIツール）の実際の順番**:
```
論外: ChatGPT
2位: Perplexity
4位: Vrew
3位: Fish Audio
1位: Google AI Studio
```

#### なぜ順番をシャッフルするのか

| 理由 | 説明 |
|------|------|
| **話の流れを優先** | 論外の説明から自然に次のツールに繋げる |
| **予測を裏切る** | 単調な昇順だと「次は3位」と予測できてしまう |
| **興味の持続** | 「次は何位？」という疑問を維持 |
| **1位は最後に固定** | クライマックスの位置だけは動かさない |

#### 順番シャッフルのパターン

```
パターンA: 論外の説明から流れるパターン
論外 → 3位（論外と関連） → 4位 → 2位 → 1位

パターンB: 完全シャッフル
論外 → 2位 → 4位 → 3位 → 1位

パターンC: 中盤に論外を挿入
論外 → 3位 → 4位 → 論外 → 2位 → 1位
```

#### 設計のルール

1. **1位は必ず最後** - これだけは絶対
2. **論外の直後は関連するツール** - 話の流れを自然に
3. **残りはシャッフル可** - 予測させない
4. **中盤の論外は任意** - 中だるみ防止に有効

---

### 「論外」の挿入タイミング

```
パターンA: 冒頭のみ
論外 → [シャッフル] → 1位

パターンB: 中盤にも挿入（推奨）
論外 → [シャッフル] → 論外 → [シャッフル] → 1位
                        ↑
                  中だるみ防止
```

中盤の「論外」は視聴者の注意を再度引きつけ、離脱を防ぐ。

### 各ランクで伝えるべき情報量

| ランク | 情報量 | 理由 |
|--------|--------|------|
| 論外 | 少（1-2文） | フックなので短く |
| 4位 | 中（2-3文） | 導入 |
| 3位 | 中（2-3文） | 価値を積み上げ |
| 2位 | 中（3-4文） | 期待値を高める |
| 1位 | 多（4-5文） | クライマックス、詳しく |

## 設計要素4：数字の「心理別」使い分け

### 数字は「何のために」使うのか

**表面的理解**: 信頼性のため
**本質**: 3つの異なる心理に訴えるため

### 数字の3つの役割

| 役割 | 訴える心理 | 例 |
|------|------------|-----|
| **目標提示** | 欲望（手に入れたい） | 「月100万」「日給3万」 |
| **証拠提示** | 信頼（本当にできる） | 「2.1億再生」「52%が初月収益化」 |
| **障壁除去** | 安心（自分にもできる） | 「30秒で」「1分で」「10分で」 |

### 使い方の公式

```
[目標の数字] + [証拠の数字] + [障壁除去の数字]
```

**実例**:
```
「月100万稼げる」（目標）
「この動画は2.1億回再生されてて」（証拠）
「1分で作れる」（障壁除去）
```

3つ揃うと「欲しい」「できそう」「やってみよう」の流れが完成する。

### 数字の「粒度」の使い分け

| 粒度 | 心理効果 | 例 |
|------|----------|-----|
| 大きな数字 | インパクト・欲望喚起 | 「2.1億再生」「月100万」 |
| 具体的な数字 | 信頼性・リアリティ | 「52%」「1件42円」 |
| 小さな数字 | 簡単さ・障壁除去 | 「30秒」「3枚」「1分」 |

## 設計要素5：「簡単さ」の演出技術

### なぜ「簡単さ」を強調するのか

**表面的理解**: ハードルを下げるため
**本質**: 「自己効力感」を与え、行動を起こさせるため

### 自己効力感とは

「自分にもできる」という確信。
これがないと、どれだけ魅力的でも行動しない。

### 「簡単さ」の5つの演出パターン

| パターン | 例 | 効果 |
|----------|-----|------|
| **時間の短さ** | 「30秒で」「1分で」「10分で」 | 時間コストの低さ |
| **操作の少なさ** | 「〜するだけ」「入力するだけ」 | 手順の少なさ |
| **スキル不要** | 「誰でも」「初心者でも」 | 能力の不要さ |
| **自動化** | 「AIが勝手に」「自動で」 | 労力の不要さ |
| **即効性** | 「一瞬で」「すぐに」 | 待ち時間の短さ |

### 実例

```
「テキストを入力するだけでこんな動画が完成」
 → 操作の少なさ + 即効性

「寝起きすっぴんでも30秒で理想の自分になれる」
 → スキル不要 + 時間の短さ + 即効性

「AIが勝手にやってくれるから、日給3万も夢じゃない」
 → 自動化 + 目標提示
```

### 「簡単さ」の配置タイミング

各ランク紹介の**後半**に配置する。

```
[ツール名] → [何ができるか] → [証拠・実績] → [簡単さ]
```

「すごい」→「本当にできる」→「自分にもできる」の流れ。

## 設計要素6：CTAの「行動設計」

### なぜ「好きな〇〇をコメント」なのか

**表面的理解**: コメントを増やすため
**本質**: 「思考コスト0」で行動させるため

### コメントの心理障壁

| 障壁 | 例 | 解決策 |
|------|-----|--------|
| **思考コスト** | 「何を書けばいいかわからない」 | 選択肢を与える |
| **恥ずかしさ** | 「変なことを書いたら」 | 正解がない質問にする |
| **面倒くささ** | 「長文を書くのが面倒」 | 1-2語で済む質問にする |

### 最強のCTA設計

```
「好きな〇〇を教えてね」
```

**なぜこれが最強か**:
1. **正解がない** → 何を書いても間違いじゃない
2. **1-2語で済む** → 「冬」「犬」「カレー」で完了
3. **考える必要がない** → 衝動的にコメントできる
4. **投稿内容と無関係でOK** → コメントしやすさ優先

### CTAキーワードの選び方

| 種類 | 例 | 特徴 |
|------|-----|------|
| **季節系** | 好きな季節 | 4択で答えやすい |
| **食べ物系** | 今日何食べた | 誰でも答えられる |
| **動物系** | 好きな動物 | 楽しい・ポジティブ |
| **二択系** | 楽天か巨人か | 選ぶだけ |
| **アニメ系** | 好きなアニメ | ターゲット層に刺さる |

### CTAの文章構造

```
「今日紹介した[具体的な内容]の[特典の形式]をまとめました。
 欲しい人は[簡単な質問]をコメントで教えてね。」
```

**実例**:
```
「今日紹介したプロンプトと、Gensparkを初心者でも使えるように
 資料にまとめたので、受け取りたい人は『好きな季節』をコメントしてね」
```

## 設計要素7：特典の「欲求喚起」設計

### 特典設計の本質

**表面的理解**: おまけをつける
**本質**: 動画内で「欲しい」という欲求を先に作り、CTAで刈り取る

### 欲求喚起の流れ

```

        ↓

        「今日紹介した〇〇をまとめました」
        ↓
Step 3: 「簡単な行動」で入手できると伝える
        「コメントで教えてね」
```

### 特典の「チラ見せ」技術

動画内で**特典の一部を使った結果**を見せる。

**実例**:
```
「このプロンプトを使ったら、寝起きすっぴんでも30秒で理想の自分になれる」
→ プロンプトの「効果」を先に見せている
→ 「そのプロンプト欲しい」という欲求が生まれる
```

```
「このプロンプトを送れば、Claudeでバズるリールを量産してくれます」
→ プロンプトの「機能」を先に伝えている
→ 「どんなプロンプト？」という興味が生まれる
```

### 特典で約束すべきもの

| 約束 | 例 | 心理効果 |
|------|-----|----------|
| **時短** | 「まとめました」「すぐ使える」 | 調べる手間を省ける |
| **再現性** | 「このまま使える」「コピペでOK」 | 失敗リスクがない |
| **独自性** | 「ここだけの」「限定」 | 希少価値 |

## 設計要素8：言葉選びの「断定」設計

### なぜ断定が効くのか

**表面的理解**: 自信があるように見える
**本質**: 「判断を委ねられる安心感」を与える

### 人は「決めてもらいたい」

情報過多の時代、人は**自分で判断することに疲れている**。
「これが正解」と断定してくれる人を信頼する。

### 断定ワードリスト

| カテゴリ | ワード | 使用シーン |
|----------|--------|------------|
| **否定** | 論外、オワコン、時代遅れ、微妙 | 推奨しないものに |
| **肯定** | 一択、最強、確実に、圧倒的 | 推奨するものに |
| **限定** | これだけ、唯一、〜しかない | 差別化に |
| **断言** | 〜です、〜ます | 全体を通して |

### 避けるべき言葉

| NG | なぜダメか | 代替 |
|----|------------|------|
| 「〜かもしれない」 | 不確実さが出る | 「〜です」 |
| 「〜と思います」 | 自信がなく見える | 「〜です」 |
| 「個人的には」 | 責任回避に見える | 削除 |
| 「おすすめかも」 | 曖昧 | 「おすすめです」「一択です」 |

### 関西弁の効果

断定 + 関西弁 = **「友達が教えてくれてる」感**

```
「ChatGPT使っとけばOKって思ってる人も多いんやけど」
→ 標準語より柔らかく、親しみやすい
→ 断定の「圧」を和らげる
```

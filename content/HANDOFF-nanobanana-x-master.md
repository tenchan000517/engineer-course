### ★講座準備の注意事項（Module 05, 06で学んだこと）★

**対象: Module 06, 07, 08, 09（すべて）**

Module 05, 06の検証で以下の問題が指摘されました。Module 06-09の準備時に必ず対応してください。

#### 0. ★最重要★ 暗黙知を排除する - 参照画像は事前準備で全て生成させる

```
❌ Bad: 「office_background.jpg を使用」（どこから入手？）
❌ Bad: 「photo.jpg はご自身の写真を使用」（持ってない人は？）
✅ Good: 事前準備セクションで全ての参照画像を生成するジェネレータを用意
```

**必須チェック項目**:
1. 講座内で使用する全ての参照画像をリストアップ
2. 各参照画像の入手方法を明記（前モジュールで生成 / 事前準備で生成 / ユーザーが用意）
3. 「ユーザーが用意」の場合は、サンプル画像を生成するジェネレータも用意
4. ファイル名は全セクションで統一（.jpg/.png の混在禁止）
5. 事前準備で生成した画像の**生成例**を講座に埋め込む

**事前準備セクションの構成**:
```markdown
## 事前準備

### Step 1: 前モジュールの画像確認
（Module 05で生成した character_sheet_yuki.png があることを確認）

### Step 2: 背景画像の生成
[ジェネレータボタン: オフィス背景]
**生成例**: ![オフィス背景](画像パス)

### Step 3: スタイル参照画像の生成
[ジェネレータボタン: ゴッホ風スタイル]
**生成例**: ![ゴッホ風スタイル](画像パス)

### Step N: サンプル人物写真の生成（任意）
（自分の写真がない人向け）
[ジェネレータボタン: サンプル写真]

### 生成した画像の確認
| ファイル名 | 用途 | 必須 |
|-----------|------|------|
| office_background.png | セクション2-2 | ✓ |
```

#### 1. テンプレートには必ず説明を追加する

```
❌ Bad: テンプレートだけ見せる
✅ Good: テンプレートの各行が何を意味するか説明テーブルを追加
```

例：
| 行 | 意味 | 例 |
|----|------|-----|
| `[CHARACTER_NAME]` | キャラクター名と説明 | `Yuki, a young anime girl` |

#### 2. ジェネレータの前にプロンプトのコードブロックを配置

```
❌ Bad: ジェネレータボタンだけ
✅ Good: 意図テーブル → プロンプトコードブロック → ジェネレータボタン → 確認ポイント
```

ユーザーはジェネレータを開かなくてもプロンプトの内容を読めるようにする。

#### 3. 手順と指示を明確に

```
❌ Bad: コードだけ見せる
✅ Good: 何をするか説明 → Step 1, Step 2... → 確認ポイント
```

#### 4. ダウンロードリンクには画像プレビューを追加

```
❌ Bad: [ダウンロード](link) だけ
✅ Good: [ダウンロード](link) + <img src="..." width="150" />
```

何をダウンロードするのか視覚的に分かるようにする。

#### 5. セマンティックなプロンプト記述

```
❌ Bad: "empty mug" （曖昧）
✅ Good: "stares at the completely dry, coffee-stained bottom - not a single drop remains" （具体的）
```

否定や状態を表現する際は、視覚的に具体的に描写する。

#### 6. 検証は複数回実施（n≧3）

1回の生成結果だけで判断しない。最低3回は生成して傾向を分析する。
